## 1. 目标 / 非目标

### 目标
1. 有 `contest.create` 的人在**网页**上建比赛：标题、题面、起止时间、计分模式、加入码、队伍规模、封榜开关。
2. 比赛**挂已有题目**（可设比赛内分值覆盖、可排序），也可把比赛设为「只对成员可见」。
3. **加入码**：私有比赛需要凭码加入；公开比赛免码。加入后成为成员；可组**队伍**（多人一队，队内共榜、共提交归属）。
4. **独立榜**：排名只在比赛内算，不影响全局 `/rank`。OI 模式（每题取最高分，按分→用时排序）与 ACM 模式（首过时间 + 罚时）两套。
5. **封榜**：比赛中/结束后按设置决定别人看得到什么；自己的名次与分数始终可见。
6. 比赛内提交**自动归属**该比赛，并在提交页标注「比赛 #N」。
7. 全部走既有细粒度权限：`contest.create`（建）、拥有者（改自己的）、`contest.manage.any`（管他人的）。

### 非目标（这一期明确不做，写进「已知限制」）
- 虚拟排名 / 参赛者在别人榜上的插位。
- 比赛中途改时限或换测试数据时对历史提交的重算。
- 队伍「队长踢人 / 转移队长」的完整 UI（先做：建队、加入队、离队、上限校验）。
- 外部账户体系、邮箱验证、比赛内判题时限单独配置（用题目自己的时限）。

## 2. 生命周期与状态

时间全部 **Unix 毫秒**（`store.nowMS()`），和现有表一致。表单用 `<input type="datetime-local">`，存库前转 UTC ms；显示用现有 `agoMS()`/本地化写法。

```
未开始 (now < start_at)
进行中 (start_at <= now < end_at)
已结束 (now >= end_at)
```
状态**永不落库**，永远由时间算出（避免定时任务、避免状态漂移）。唯一的落库开关是
`standing_open`（封榜：`0=只给自己看，1=公示`）与 `visible`（比赛本身是否出现在列表）。

三条关键不变量：
1. **题目可见性**：`problems.visible` 只管全站；比赛挂题即对**该赛成员**放开判题入口（见 §6 提交门禁）。非成员即使题目 `visible=1` 也看不到比赛内视图。
2. **封榜不泄露题面/数据**：封榜只影响 *别人* 的明细；题面本身按 §6 的成员判定决定。
3. **提交归属不可变**：一次提交在创建时确定属于哪个比赛（`contest_id`，0=平时练习），之后改名单/退队都不追溯。

## 3. 数据层：`internal/store/migrations/0013_contests.sql`

```sql
-- 0013: 比赛。计分复用 M13 的 runs.score，比赛只管「谁在什么时间对哪些题交了什么」。
CREATE TABLE contests (
    id            INTEGER PRIMARY KEY,
    cid           TEXT    NOT NULL UNIQUE COLLATE NOCASE,   -- 人类可读编号，URL 用它：/contests/C0001
    title         TEXT    NOT NULL,
    statement     TEXT    NOT NULL DEFAULT '',              -- Markdown + KaTeX，与题面同一渲染管线
    start_at      INTEGER NOT NULL,
    end_at        INTEGER NOT NULL CHECK (end_at > start_at),
    mode          TEXT    NOT NULL DEFAULT 'oi' CHECK (mode IN ('oi','acm')),
    join_code     TEXT    NOT NULL DEFAULT '',              -- 空 = 公开赛，任何人可进
    standing_open INTEGER NOT NULL DEFAULT 0,               -- 0 封榜 / 1 公示
    visible       INTEGER NOT NULL DEFAULT 1,               -- 是否出现在 /contests 列表
    team_size     INTEGER NOT NULL DEFAULT 1 CHECK (team_size BETWEEN 1 AND 5),
    penalty_ms    INTEGER NOT NULL DEFAULT 1200000,         -- ACM 罚时：每次未过尝试 20 分钟
    owner_id      INTEGER REFERENCES users(id),
    created_at    INTEGER NOT NULL,
    updated_at    INTEGER NOT NULL
);

CREATE TABLE contest_problems (
    contest_id  INTEGER NOT NULL REFERENCES contests(id) ON DELETE CASCADE,
    problem_id  INTEGER NOT NULL REFERENCES problems(id) ON DELETE CASCADE,
    ordinal     INTEGER NOT NULL,                           -- 比赛内顺序（A/B/C…）
    points      INTEGER NOT NULL DEFAULT 0,                 -- 0 = 沿用题目自身满分
    label       TEXT    NOT NULL DEFAULT '',                 -- 「A」「B」；空则按 ordinal 生成
    PRIMARY KEY (contest_id, problem_id)
);
CREATE UNIQUE INDEX uq_contest_problem_ordinal ON contest_problems(contest_id, ordinal);

CREATE TABLE contest_teams (
    id         INTEGER PRIMARY KEY,
    contest_id INTEGER NOT NULL REFERENCES contests(id) ON DELETE CASCADE,
    name       TEXT    NOT NULL,
    created_at INTEGER NOT NULL,
    UNIQUE (contest_id, name) COLLATE NOCASE
);

CREATE TABLE contest_members (
    contest_id INTEGER NOT NULL REFERENCES contests(id) ON DELETE CASCADE,
    user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    team_id    INTEGER NOT NULL REFERENCES contest_teams(id) ON DELETE CASCADE,  -- 0 = 单打（无队）
    role       TEXT    NOT NULL DEFAULT 'member' CHECK (role IN ('owner','member')),
    joined_at  INTEGER NOT NULL,
    PRIMARY KEY (contest_id, user_id)
);
CREATE INDEX idx_members_contest ON contest_members(contest_id, team_id);

-- 提交归属比赛；0 是练习。加列带默认值，旧行不用回填。
ALTER TABLE submissions ADD COLUMN contest_id INTEGER NOT NULL DEFAULT 0;
CREATE INDEX idx_submissions_contest ON submissions(contest_id, user_id, problem_id, id);
```

注：`team_id` 用 `REFERENCES ... ON DELETE CASCADE` 但允许 0（SQLite 的外键对 0 会失败——
**改用**：`team_id INTEGER NOT NULL DEFAULT 0`，并在 `foreign_keys(1)` 下**去掉该列的 REFERENCES**，
由 store 层保证一致性；`contest_teams` 删除时先显式把成员的 `team_id` 置 0。这条要么这么改，
要么改成允许 `NULL` 并统一按 `IFNULL(team_id,0)` 读。**推荐后者**：
`team_id INTEGER REFERENCES contest_teams(id) ON DELETE SET NULL` + 读取一律 `IFNULL(team_id,0)`。）

`cid` 用 `C0001` 风格由 store 生成（复用 `CreateProblem` 里 pid 的生成方式；若现在 pid 由用户填，
那比赛也允许用户填 `cid`，留空时自动生成 `C` + 4 位）。**保持和用户习惯一致：允许填、可空自动生成。**

## 5. 加入门禁（`JoinContest` 与页面共用一份判定）

按顺序判，第一条不满足即拒绝并给**中文**原因（现有 flash 风格）：

1. 比赛存在；
2. 非成员（已是成员 → 幂等成功，别报错，参考 `Follow` 的幂等做法）；
3. `join_code == ""`（公开）**或** 提交的码等于 `join_code`；比较用 `subtle.ConstantTimeCompare`（虽然是网页，泄漏只差一个码，成本为零）；
4. **未结束**（`now < end_at`）才允许首次加入——进行中可加入，已结束不可（避免「赛后补进榜」）；
5. 队伍：`team_size == 1` 时 `teamID` 必须为 0；否则若指定 `want` 队名 → 加入该队（校验队存在、属于本赛、人数 < `team_size`），不指定 → 自动新建以队长 handle 命名的队。
6. `role`：`owner_id == userID` 的人写入 `role='owner'`，其余 `'member'`。

**join code 的显示规则**：只有 `canManageContest` 的人在管理页看得到；任何列表/榜/详情页都不得出现；加入表单 POST 成功后**不要**把码回显，也不放 URL。

权限判定函数放 `internal/api/perms.go`，与 `canEditProblem` 并列：

```go
func (a actor) canManageContest(c store.Contest) bool {
    if a.can(permContestManageAny) { return true }
    return c.OwnerID != 0 && c.OwnerID == a.User.ID
}
func (a actor) isContestMember(c store.Contest) bool // 一次 store.ContestMemberOf
```
`viewer` 加 `Contests bool`（= `contest.create || contest.manage.any`），导航栏加「比赛」入口。

## 6. 计分（这是本文档的核心，别猜）

### 6.1 提交归属
- 从比赛页点进去的题面页 URL：`/contests/{key}/p/{label}`，服务端解析出 `(contest, problem)`，提交表单 action 仍是 `POST /problems/{key}/submit`，但**加一个隐藏字段** `contest=<contest_id>`。
- `createSubmission`（`internal/api/web.go`）多接一个 `contestID int64`，写库前校验：
  - `contestID == 0` → 练习，照旧；
  - 否则要求：比赛进行中（`start_at <= now < end_at`）**且**提交者是成员；不满足 → flash「这场比赛还没开始 / 已经结束 / 你还不是成员」，**不入库**。
  - 题目必须挂在该比赛里（`contest_problems` 有行），否则视为非法归属。
- `submissions.contest_id` 落库；提交详情页显示「比赛 <cid>」并链回该赛榜。

### 6.2 每题得分（复用 M13，不改一行 tally 逻辑）
`runs.score` 已经是「这条用例实际挣到几分」（组内全过才有分）。所以：

```
perSubmissionPoints(sub) = SELECT IFNULL(SUM(score),0) FROM runs WHERE submission_id=? 
                            AND case 是判题用例（runs 里 IsSample=false）
```
题目满分 = `store.ProblemScoreTotal(problemID)`，若 `contest_problems.points > 0` 则**按比例折算**：
`award = round(rawScore * cp.points / total)`，`total==0` 时按 0 分处理（该题还没数据）。
> 折算规则要写进 UI 提示：`比赛内分值 = 题目分值 × (比赛设定分 / 题目满分)`，避免出题人以为能凭空加分。

### 6.3 「OI 模式」（M18 起改名为 IOI 模式）

> **M18 返修**：这一节写的其实是 **IOI** 的规则。真正的 OI（CSP-J/S、NOIP、NOI）取**最后一次**提交、
> 同分同名次、比赛中不出榜。本文其余地方出现的「OI 模式」一律按 §15 理解；这一节的算法原样保留为
> `mode='ioi'`。

- 每人每题取**最高** `award`（不是最后一次！这与国内 OI 惯例一致，README 要写清）。
- 同分**取该最高分那次提交的用时**（`judged_at - start_at`），全部题的用时求和 = `total time`。
- 排名键：`(score DESC, time ASC, handles[0] ASC)`。
- `cell` 显示：`得分/本题满分`，尝试次数小字。
- CE/WA/TLE/MLE 一律 0 分但计入尝试次数。

### 6.4 ACM 模式
- 一次题只算**首次 AC**：`firstACJudgedAt = MIN(judged_at) WHERE verdict='AC'`；该题得分 = 满分（ACM 不认部分分，**但**若题目带组/部分分，AC 仍要求全过——即 `verdict=AC` 已由 M13 保证，无需特判）。
- 罚时 = `(该题首次 AC 之前的非 AC 判定次数) × penalty_ms` + `firstACJudgedAt - start_at`；未 AC 的题只计尝试次数、不给时间。
  - 非 AC 计数只算 `WA/RE/TLE/MLE`；`CE` **不罚**（国际惯例），`IE` 不罚且不算尝试。
- 排名键：`(solved DESC, penalty ASC, handles[0] ASC)`。
- `cell` 显示：`尝试次数(+)`，AC 时前面加时间 `mm:ss` 风格用现有 `formatMS` 思路（写个 `formatPenalty(ms)` 放 `problems.go` 的格式化旁边）。
- 判题中/排队中的提交**不入榜**（与全局一致：只算 `status='done'`）。

### 6.5 榜单 SQL 的实现约束
- **一条查询**取全赛数据，禁止「一人一题一次查询」：
  ```sql
  SELECT m.user_id, IFNULL(m.team_id,0) AS team, cp.problem_id, s.id, s.verdict, s.status,
         s.judged_at, s.created_at,
         (SELECT IFNULL(SUM(r.score),0) FROM runs r JOIN testcases t
             ON t.problem_id = s.problem_id AND t.name = r.case_name
          WHERE r.submission_id = s.id AND t.is_sample = 0) AS raw_score
    FROM contest_members m
    JOIN contest_problems cp ON cp.contest_id = m.contest_id
    LEFT JOIN submissions s ON s.user_id = m.user_id AND s.problem_id = cp.problem_id
                           AND s.contest_id = m.contest_id AND s.status = 'done'
   WHERE m.contest_id = ?
   ```
  然后**在 Go 里聚合**（OI 取 max、ACM 取首过），避免 SQLite 里写窗口/相关子查询地狱。
  成员数 × 题数 × 提交数 可控（几百行级），够快；真要再快加 `idx_submissions_contest`（§3 已给）。
- 队伍模式：`GROUP BY team_id` 时，队内每人在每题的贡献取**队内最优**（这是队伍赛的通行规则），
  尝试次数取**队内求和**（罚时按队算）。单打行（`team_id=0`）退化为按个人。
- 显示名：`team_id=0` → handle；否则队名 + 成员 handle 列表。

## 8. 封榜与「自己看自己」

`GET /contests/{key}/standings`：

- `standing_open == 1`，或 `now >= end_at && standing_open == 1` → 全榜。
- 否则（封榜）：
  - 管理侧（`canManageContest` 或持 `contest.manage.any`）→ 全榜 + 顶栏「（封榜中）」灰标；
  - 成员 → **只给一行自己的**（名次 + 分数 + 每题得分），名次用 `ContestSelfSeed` 算（含所有参赛者的真实排名，不泄露他人数据）；
  - 非成员 → 「本场暂未放榜」。
- 结束后若 `standing_open==0`：仍然封（**不自动公示**）。管理页有一个开关「公示榜单」，
  赛后手动打开——这是刻意的，避免「忘了改设置就泄题」。

## 9. 边界与坑（每条都来自现有代码的同类教训）

1. **N+1**：列表页一场比赛一次查询拿计数（`GROUP BY contest_id` + `IN` 列表），照 `store.CaseCounts/ProblemCounts` 的写法。
2. **`FindContest` 的数字/编号二义**：照 `FindProblem` 那样先试纯数字 id，再按 `cid`；注意 `C0001` 不会被误判成 id。
3. **ordinal 唯一**：交换 ordinal 时要**先腾位**（把两个值分别 UPDATE，或用临时 -ordinal 技巧），否则撞 `uq_contest_problem_ordinal`；放进一个 `InTx`。
4. **删除比赛**：成员/队/挂题级联删；历史提交的 `contest_id` **保留**，提交页显示「比赛已删除」而不是 404（别外链一个不存在的路径）。
5. **队伍人数**：`team_size` 改小时**不追溯**（已在超编队伍里的人继续待着），但禁止新加入；提示文案说明这点。
6. **改名**：`cid` 允许改，表单 action 与所有链接用 `Contest.CID` 而不是用户输入值（照 `editData.Key` 的处理，避免失败回填后指向不存在的地址）。
7. **时间**：`datetime-local` 无时区；**约定按本地时区提交、服务端按 UTC 解析**并在表单旁写明（现有站点没涉及时区，别自创第二套；建议：表单多带一个隐藏 `tz` 分钟偏移，服务端换算 ms，显示一律用 `agoMS` 相对时间，避免绝对时间歧义）。
8. **join code 泄漏**：不出现在列表、榜、URL、日志（`s.log.Info` 别打表单值）；管理页里以 `<code>` 显示并可重新生成（`POST /contests/{key}/code` → 生成新码，flash 一次）。
9. **进行中改题**：移题/换题后历史提交仍计入（`contest_id` 归属不变），榜单里该题列显示「已移除」；**不要**删提交。
10. **重复提交并发**：OI 取最高分天然幂等；ACM 首过用 `MIN(judged_at)`，两次几乎同时判完也不会错。
11. **判题中不入榜**：一律 `status='done'` 过滤，与提交列表一致。
12. **权限矩阵页**：`/admin/perms` 已经能开关 `contest.*`（键已存在），无需改；但**新增的 `viewer.Contests`** 要在 `a.viewer()` 里赋值，否则导航栏不出现入口。
13. **匿名访问**：比赛主页/榜要能匿名访问（公开赛的宣传），但题面、成员名单在封榜期/未开始时对非成员隐藏；判定顺序写成一个函数 `contestVisibility(a, c, now)` 返回 `{Joined, CanManage, ShowProblems, ShowMembers}`，页面与 store 查询共用，别在模板里散落 `if`。
14. **提交门禁的绕过面**：`POST /problems/{key}/submit` 是唯一的提交入口，`contest` 字段来自表单——**服务端必须重验**成员/时间，不能信表单。
15. **不要引入定时任务**：状态由时间算出，见 §2。

## 15. M18 返修：OI 与 IOI 分家

§13 那一处拍板拍错了：把 **IOI 的算法**（每题取最高分、同分比总用时）按在了 **OI** 这个名字上，
而本项目面向的就是 CSP-J/S、NOIP、NOI 这批选手，默认赛制必须是中国 OI 的规矩。规则核对后如下：

| | OI（CSP-J/S、NOIP、NOI） | IOI | ACM |
|---|---|---|---|
| 同一题多次提交 | **取最后一次** | 取最高分 | 只认首次 AC |
| 同分 | **同名次**，不比任何附加项 | 比总用时 | 比罚时 |
| 比赛进行中 | **不出榜**，除主办方外连自己那一行都没有 | 出榜 | 出榜 |
| 榜上有没有用时/罚时 | **都没有**，也没有尝试次数 | 有用时 | 有罚时 |
| 提交后能否立刻看结果 | 真实比赛不能（配套：把题目详情级别设为 `none`） | 能 | 能 |

落地改动，仍是三次小步提交、每次 `go test ./...` 全绿：

1. **M18a 数据层与算分**（`0015_oi_and_ioi.sql` + `internal/store/contest.go`）
   - `mode` 的 CHECK 从 `('oi','acm')` 变成 `('oi','ioi','acm')`。SQLite 改不了已有列的 CHECK，
     所以按官方那套重建四张比赛表：建新表 → 搬数据 → **先丢子表再丢父表**（反过来会顺着
     `ON DELETE CASCADE` 把刚搬好的数据删掉）→ **父表先改名**（SQLite 会顺手把其他表外键里的表名改掉）→ 重建索引。
     整个过程在 `store.migrate` 的一个事务里，配套测试 `TestContestModeCheckAfterTheRebuild`
     带 `PRAGMA foreign_key_check`，防止重建后外键指向已经消失的 `*_new`。
   - `problemStat` 记下**最后一次判出的分数**；`IE` 是判机坏了，不把它当成"最后一次提交"，
     否则一次基础设施故障就能把已经拿到手的高分抹成 0。
   - OI 不累计 `TimeMS`，名次键只有 `(-score)`，所以同分必然同名次。
   - `Contest.BoardLive(now)` 把"比赛中不出榜"写成赛制本身的一条规则，而不是一个更友好的默认值。
2. **M18b 网页榜单**：OI 进行中的 standings 对非主办方返回一段解释而不是空表；OI 的格子只剩一个
   数字（无用时列、无尝试次数）；罚时那句话说实话了——只有 ACM 用得上那个设置，OI/IOI 显示「本赛制不比罚时」。
3. **M18c 文案与文档**：建赛表单三个选项各写各的规则，README 的[比赛](../../README.md#比赛限时--独立榜--加入码--队伍oiioiacm-三种赛制)
   一节按三种赛制分开写，§6.3 顶部留了这条返修的指针。

**升级已有数据的取舍**：老比赛里 `mode='oi'` 的那些，语义在升级后**变了**——原来算最高分，现在算最后一次。
没有做数据迁移（不把老 `oi` 悄悄改名成 `ioi`），理由是：这个 CHECK  widening 只影响算分口径，
而主办方要的正确口径由 `mode` 这一个字段决定；把历史比赛自动改名为 `ioi` 会让"我建的是 OI 赛制"这句
用户可见的话在同一场对上变成假话。已在 README「已知限制」写明升级后应复核老比赛的赛制。
